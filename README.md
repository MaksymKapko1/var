# Variational Omni Grid Bot (testnet)

Простой грид-бот для **Variational Omni API** на Python, в Docker. Все ключи и настройки берутся из `.env`, поэтому один и тот же код можно запускать на разных серверах с разными ключами.

Документация API: https://docs.variational.io/api-documentation/overview.
Omni API пока в early access и **работает только на testnet**: `https://api.omni.testnet.variational.io`.

## Как работает

Бот ставит настоящие лимитные ордера через `POST /v1/orders`.

1. Диапазон `GRID_LOWER..GRID_UPPER` делится на `GRID_LEVELS` уровней.
2. На старте ниже цены ставятся BUY-лимитки, выше цены ставятся SELL-лимитки. Уровень, ближайший к цене, остаётся пустым.
3. Если исполнился **BUY на уровне i**, бот ставит **SELL на уровне i+1**.
   Если исполнился **SELL на уровне i**, бот ставит **BUY на уровне i-1**.
4. Каждая пара buy и sell приносит примерно `шаг сетки × ORDER_SIZE`. В логах ведётся статистика `round_trips` и `grid_profit`.
5. Раз в `POLL_INTERVAL_SEC` бот запрашивает `GET /v1/orders?symbol=`. Если ордер пропал из открытых, бот смотрит его через `GET /v1/orders/{id}`. Статус `filled` означает, что ставится встречный ордер. Статус `rejected` или `canceled` означает, что ордер будет переставлен через 60 секунд.

Это **нейтральный грид на перпе**: SELL выше цены открывает шорт. Позиция держится в пределах ±(`GRID_LEVELS`-1)×`ORDER_SIZE`.

Особенности Omni, которые учтены в коде:
- лимитки исполняются только целиком (all-or-nothing), исполняются по quoted price OLP;
- на один инструмент можно держать не больше 50 ордеров;
- цена округляется по `price_precision`, размер по `size_step`, проверяется `min_notional`;
- у каждого ордера есть уникальный `client_order_id`. При обрыве связи или ответе `outcome_unknown` бот ищет ордер по этому id, поэтому дублей не будет;
- **лимит запросов: 60 weight в минуту**, за повторные превышения дают бан до 24 часов. Бот следит за заголовками `X-RateLimit-*` и делает паузу заранее, а на 429 ждёт `retry_after_ms`;
- запросы подписываются ключом Ed25519. Подпись проверена тестом на векторе из документации.

Состояние сетки (какие ордера на каких уровнях) хранится в `./data/state.json`. После рестарта контейнера бот продолжает с того же места. Если поменять параметры сетки, бот отменит ордера на символе и построит сетку заново.

При `docker stop` бот отменяет свои ордера, если `CANCEL_ON_EXIT=true`. **Открытая позиция при этом не закрывается.**

## Что нужно

1. Кошелёк (MetaMask, Rabby и т.п.). Лучше отдельный, тестовый.
2. Зайти в Omni testnet, подключить кошелёк, получить тестовые USDC и внести депозит.
3. В веб-приложении Omni создать **API key** со scope **`trade`**. Ключ со scope `read` ордера ставить не может.
   Ключ состоит из двух частей:
   - **public key** `0x…64 hex` идёт в `VAR_API_KEY`;
   - **private key**, 32 байта в hex, показывается один раз, идёт в `VAR_API_SECRET`.
   Новый ключ может заработать через несколько секунд.

Приватный ключ кошелька боту **не нужен**.

## Запуск

```bash
cp .env.example .env
```

```bash
nano .env
```

Проверка: ключ, баланс, список инструментов, `min_notional`, `size_step`, цена, позиция.

```bash
docker compose run --rm gridbot check
```

Запуск с `DRY_RUN=true`: бот только показывает в логах, какие ордера поставил бы.

```bash
docker compose up -d --build
```

```bash
docker compose logs -f
```

Если план в логах устраивает, поставь в `.env` `DRY_RUN=false` и перезапусти:

```bash
docker compose up -d
```

### Несколько серверов или ботов

На каждом сервере: `git clone`, затем `cp .env.example .env`, вписать свои ключи и запустить `docker compose up -d --build`.

Несколько ботов на одном сервере запускай из разных папок. У каждой папки свой `.env`, свой `data/` и свой `BOT_ID`. Если боты используют один аккаунт, давай им **разные символы**: на старте бот отменяет все ордера на своём символе.

## Переменные `.env`

| Переменная | Что это |
|---|---|
| `VAR_API_KEY` | public key (`0x` + 64 hex). Можно не указывать, он выводится из приватного |
| `VAR_API_SECRET` | private key Ed25519 (64 hex) |
| `VAR_BASE_URL`, `VAR_ENVIRONMENT` | `https://api.omni.testnet.variational.io` и `testnet` |
| `SYMBOL` | например `ETH-PERP`, `BTC-PERP` |
| `GRID_LOWER`, `GRID_UPPER`, `GRID_LEVELS` | границы и число уровней (3–50) |
| `ORDER_SIZE` | размер одного ордера в базовом активе |
| `TRIGGER_BY` | `quote` или `mark` |
| `MAX_SLIPPAGE` | доля от mark, например `0.02`; `none` значит без ограничения |
| `BOT_ID` | префикс `client_order_id` |
| `POLL_INTERVAL_SEC` | период опроса, по умолчанию 15 секунд |
| `DRY_RUN` | `true` значит без реальных ордеров |
| `CANCEL_ON_EXIT` | отменять ордера при остановке |
