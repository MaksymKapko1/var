# Variational Omni Grid Bot

Автономный грид-бот для **Variational Omni API** (testnet). Написан на Python 3.12 с asyncio и упакован в Docker. Ключи и настройки берутся из `.env`, поэтому один и тот же код можно запускать на любом количестве серверов.

API: https://docs.variational.io/api-documentation/overview. Сейчас доступен только testnet: `https://api.omni.testnet.variational.io`.

## Быстрый старт на сервере

```bash
git clone -b claude/gallant-clarke-ccvua0 https://github.com/maksymkapko1/var.git gridbot && cd gridbot
```
```bash
sudo bash deploy/server-setup.sh      # один раз: Docker + compose (Ubuntu/Debian)
```
```bash
cp .env.example .env && nano .env     # VAR_API_SECRET, диапазон сетки, размер
```
```bash
make check                            # ключ, scope trade, баланс, инструмент
```
```bash
make up && make logs                  # DRY_RUN=true: только план в логах
```
Если план устраивает, поставь в `.env` `DRY_RUN=false` и выполни `make up`.

### Деплой с локальной машины на несколько серверов

```bash
mkdir envs && cp .env.example envs/eth.env && nano envs/eth.env
```
```bash
./deploy/deploy.sh root@1.2.3.4 envs/eth.env gridbot-eth
```

Скрипт копирует код и `.env` на сервер, запускает `check` и поднимает контейнер. Папка `envs/` в git не попадает.

## Стратегия «ротация» (рыночные позиции)

Отдельный контейнер со своим конфигом `.env.rotation`. Он держит рыночные позиции по списку ног, например BTC лонг, ETH шорт, HYPE лонг, SOL шорт, и **раз в час закрывает их и открывает заново**. PnL не цель, стратегия нужна для объёма на testnet.
- Размер ноги: `ROTATION_MARGIN_USDC` × плечо рынка (плечо берётся из аккаунта). 100$ при 50x дают 5000$ позиции. Можно задать объём напрямую через `ROTATION_NOTIONAL_USDC`.
- Раз в `ROTATION_CHECK_SEC` бот проверяет, что все ноги на месте. Пропавшую позицию (ликвидация, ручное закрытие, отказ ордера) добирает, позицию не в ту сторону переворачивает.
- Расписание переживает рестарт: перезапуск контейнера не вызывает внеплановую ротацию.

```bash
cp .env.rotation.example .env.rotation && nano .env.rotation
```
```bash
make rot-check
```
```bash
make rot-up && make rot-logs
```

Команды: `rot-status`, `rot-stop`, `rot-close` (закрыть всё и встать в СТОП), `rot-resume`.

⚠️ **Грид и ротация на одном аккаунте не должны торговать одним символом.** Позиция на символе одна на весь аккаунт, и боты будут мешать друг другу. Например, грид на ETH-PERP увидит шорт ротации и сработает аварийный стоп. Дай гриду другой `SYMBOL`. Лимит API общий на аккаунт, поэтому каждому боту ставь `RATE_LIMIT_PER_MIN=30`.

На сервере ротацию можно запустить и как основной бот: в `.env` укажи `STRATEGY=rotation` и параметры `ROTATION_*`, затем `deploy.sh` как обычно.

## Стратегия «bracket»: US500 и золото, TP/SL

Трендовый скальпер для отдельного аккаунта, по умолчанию на `US500-PERP` и `XAU-PERP`. Работает так:
1. Раз в 10 секунд бот берёт mark price и считает быструю и медленную EMA. Если быстрая выше, тренд вверх и бот покупает, иначе продаёт.
2. Когда позиции нет, ставит **лимитный вход** по тренду на 1 б.п. лучше рынка, сразу с **take-profit (+0.10%)** и **stop-loss (−0.20%)** одним запросом.
3. Если вход не исполнился за 90 секунд, отменяет его и переставляет по новой цене.
4. Позицию закрывает TP или SL. Если она висит дольше 30 минут, бот закрывает её по рынку.
5. TradFi-рынки работают по сессиям: пока рынок закрыт, бот ждёт. За 5 минут до закрытия сессии закрывает позицию.
6. Ошибка на одном символе не останавливает другой. Отказы обрабатываются с растущей паузой.

Локально:
```bash
cp .env.bracket.example .env.bracket && nano .env.bracket
```
```bash
make br-check
```
```bash
make br-up && make br-logs
```

Команды: `br-status`, `br-stop`, `br-close`, `br-resume`.

На сервер (свой `.env`, другой аккаунт):
```bash
mkdir -p envs && cp .env.bracket.example envs/gold.env && nano envs/gold.env
```
```bash
./deploy/deploy.sh root@IP envs/gold.env gridbot-gold
```

## Команды

| Команда | Что делает |
|---|---|
| `make up` | собрать и запустить в фоне с авто-рестартом |
| `make logs` | логи в реальном времени |
| `make ps` | статус контейнера и healthcheck |
| `make check` | проверить ключ (включая scope `trade`), баланс, инструмент |
| `make status` | режим бота, позиция, открытые ордера, ошибки в очереди |
| `make stop` | остановить бота. Ордера остаются, после `make up` он продолжит с того же места |
| `make cancel` | остановить и снять все ордера на `SYMBOL` |
| `make close` | остановить, снять ордера и **закрыть позицию по рынку**, режим СТОП |
| `make resume` | снять режим СТОП и запустить заново (сетка строится от текущей цены) |
| `make update` | `git pull`, пересборка, перезапуск |

## Архитектура

```
gridbot/
  __main__.py        CLI: run | check | status | cancel | close | resume
  config.py          конфиг из env с валидацией
  exchange/
    signer.py        подпись Ed25519 (проверена на векторе из документации)
    ratelimit.py     лимитер по weight: скользящее окно + синхронизация с X-RateLimit-*
    client.py        async httpx-клиент: ретраи, коррекция часов, идемпотентные ордера
    errors.py        классификация ошибок и отказов -> паузы и повторы
  strategy/
    grid.py          чистая логика сетки (уровни, начальная раскладка, встречные ордера)
    precision.py     округление цены (price_precision) и размера (size_step)
  core/
    engine.py        старт и восстановление, торговый цикл, риск-цикл, остановка
    orders.py        размещение, сверка, обработка отказов, cancel_all, закрытие позиции
    state.py         состояние на диске (атомарная запись)
    watchdog.py      поток-сторож: heartbeat для healthcheck и аварийный рестарт при зависании
```

### Стратегия
Два режима сетки:
- **Авто** (`GRID_STEP_PCT`, по умолчанию). Узкая сетка строится вокруг текущей цены с шагом в %. Если цена ушла за край сетки, бот снимает ордера, закрывает позицию по рынку (при `RECENTER_FLATTEN=true`) и **перестраивает сетку вокруг новой цены**. Сделки идут постоянно, это удобно для теста testnet.
- **Фикс** (`GRID_LOWER`/`GRID_UPPER`). Диапазон задаётся руками. При выходе цены за него бот действует по `RANGE_EXIT_ACTION`: пауза, закрытие позиции или ничего.

Диапазон делится на `GRID_LEVELS` уровней. Ниже цены ставятся BUY-лимитки, выше цены SELL-лимитки. Уровень, ближайший к цене, остаётся пустым.
- Исполнился BUY на уровне i: бот ставит SELL на уровне i+1.
- Исполнился SELL на уровне i: бот ставит BUY на уровне i-1.

Каждое исполнение встречного ордера закрывает цикл и приносит примерно `шаг × размер`. В логах это `циклов` и `профит сетки`.

Это нейтральный грид на перпе: позиция колеблется в пределах ±(уровни-1)×размер.

### Rate limit (60 weight в минуту, за превышения бан до 24 часов)
- Каждый запрос сначала проходит через лимитер. Он считает вес в скользящем окне 60 секунд и подстраивается под заголовки `X-RateLimit-Remaining` и `X-RateLimit-Reset` от биржи.
- Обычные запросы не трогают последние `RATE_LIMIT_RESERVE` weight. Этот резерв оставлен для отмены ордеров и закрытия позиции в аварийной ситуации.
- Если всё же пришёл 429 или `banned`, бот выдерживает паузу `retry_after_ms` для **всех** запросов.
- В обычном режиме бот тратит примерно 8–10 weight в минуту. Расстановка сетки на старте растягивается по времени автоматически.

### Обработка отказов
- **Ордер отклонён биржей при исполнении** (`rejected`: `quote_unavailable`, `insufficient_margin`, `price_check_failed` и т.д.). Уровень попадает в очередь с паузой, которая зависит от причины и растёт экспоненциально до 30 минут. Видно в `make status`.
- **Ошибка HTTP при размещении** (`invalid_price_increment`, `too_many_orders`, `market_not_trading` и т.д.). Пауза зависит от кода. Если ошибка связана с округлением, бот перечитывает правила инструмента.
- **Сеть, таймаут, `outcome_unknown`.** Повтор с тем же `client_order_id`: биржа вернёт уже существующий ордер, дубля не будет.
- **Ордер отменён не ботом** (вручную или системой). Бот переставит его.
- **Часы сервера расходятся с биржей.** Бот берёт время сервера из ответа и сам корректирует подпись.
- **Ключ не принят** (401/403). Бот пишет понятную ошибку и ждёт 120 секунд перед рестартом, чтобы не долбить API.

### Риск-контроль
| Условие | Действие |
|---|---|
| цена вышла за сетку больше чем на `RANGE_EXIT_PCT` % | `recenter` (авто): перестроить сетку вокруг цены, позиция закрывается при `RECENTER_FLATTEN`. `pause`: снять ордера и ждать возврата цены, потом перестроить. `close`: снять ордера, закрыть позицию, СТОП |
| PnL позиции ≤ −`MAX_LOSS_USDC` | снять ордера, закрыть позицию, СТОП |
| позиция > `MAX_POSITION_MULT` × (уровни-1) × размер | снять ордера, закрыть позицию, СТОП (защита от ручных сделок и багов) |

Позиция закрывается рыночным reduce-only ордером. Если не вышло, бот повторяет до 6 раз и каждый раз расширяет допустимое проскальзывание.

Режим **СТОП** сохраняется на диск. После рестарта бот не начнёт торговать сам, нужен `make resume`.

### Автономность и перезапуск
- `restart: unless-stopped`: контейнер поднимается после падения и после ребута сервера (`server-setup.sh` включает автозапуск Docker).
- Состояние лежит в docker volume. После рестарта бот сверяет свои ордера с биржей и продолжает работу. Исполнения, которые случились, пока он лежал, тоже учитываются.
- Если поменять параметры сетки в `.env` и выполнить `make up`, старые ордера снимутся, а сетка построится заново.
- Watchdog: если цикл завис больше чем на `WATCHDOG_SEC`, процесс завершается, и Docker его перезапускает. Healthcheck показывает `unhealthy`, если heartbeat не обновлялся 3 минуты.
- 30 ошибок подряд приводят к выходу и чистому рестарту контейнера.
- Логи ротируются (5 × 20 МБ), есть лимиты памяти и CPU.

## Настройки

Все переменные с комментариями описаны в [`.env.example`](.env.example). Главные:

| Переменная | По умолчанию | |
|---|---|---|
| `VAR_API_SECRET` | — | приватный ключ Ed25519 (64 hex), ключ должен иметь scope **trade** |
| `SYMBOL` | `ETH-PERP` | любой из `make check` |
| `GRID_STEP_PCT` | `0.1` | авто-сетка: шаг в %. Меньше шаг означает чаще сделки |
| `GRID_LEVELS` | 10 | число уровней |
| `GRID_LOWER`/`GRID_UPPER` | — | фиксированный диапазон, тогда `GRID_STEP_PCT` оставь пустым |
| `RECENTER_FLATTEN` | `true` | закрывать позицию при перестройке |
| `GRID_BALANCE_PCT` или `ORDER_SIZE` | — | % equity на всю сетку **или** монет на один ордер |
| `RANGE_EXIT_ACTION` | `recenter` | `recenter` / `pause` / `close` / `none` |
| `MAX_LOSS_USDC` | выкл | стоп по убытку |
| `CANCEL_ON_EXIT` / `CLOSE_ON_EXIT` | `false` | что делать при `docker stop` |
| `DRY_RUN` | `true` | без реальных ордеров |

```bash
pip install -r requirements.txt -r requirements-dev.txt && python -m pytest -q
```

Без Python на машине: `make test` (тесты в Docker). Они покрывают подпись (вектор из документации), округление (таблица из документации), лимитер, HTTP-клиент на mock-транспорте (ретраи, 429, коррекция часов, дубли) и сценарии движка на фейковой бирже: исполнения, отказы, рестарт, смена параметров, выход из диапазона, стоп-лосс, закрытие.
